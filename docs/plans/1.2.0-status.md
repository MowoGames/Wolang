# 1.2.0: where it stands

Written 2026-10-31 on branch `feature/1.2.0`, which is 8 commits ahead of
`alpha` and has not been pushed. The plan is [1.2.0.md](1.2.0.md); this file
says what is done, what is not, and what comes after. The engine's wish
list is in [engine-needs.md](engine-needs.md).

## Unverified D235

Compile first, then run `wl test TypeCheck`, `CodegenTest`, `AotTest`, `wl lib`,
`wl docs`, `wl fuzz 200`. Likely trouble:

- `Parser::ParseErrorList` and the `!` loop: an identifier after `!` on the same
  line is read as an error name.
- `TypeStore::StatedErrorSet` pre-interns `Optional(detail)`; `FindOptional` in
  the layout depends on it.
- `Erase(kFallible)` keeps only payload errors in the set; every comparison of an
  erased fallible with an unerased one is a place to look.
- `Coerce` into a `T!`: the boxed branch and the rebuild between two payload
  layouts, and who frees a slot after `?` (`IsFreshHandle` on `MakeStruct`).
- A payload error held in a `const` before it reaches a `T!` is a tuple and is not
  counted: it leaks its box.
- Library sets were read off the code by eye (client, image, db, json, yaml,
  toml, regex, compress); `wl lib` will show any missing one as `E0151`.
- Test sources that match on a bare `T!` with no `_` arm are `E0201` now; the ones
  in `codegen_unittest.cc`, the libraries and the docs were changed by hand.
- Tag-hash collisions between two modules are not diagnosed (plan said E0057).
- The three parser/formatter/lowering tests were first written with real newlines
  inside string literals and rewritten in the fuzzer commit.

## Unverified D236 and D237

Written with no build. Compile first, then `wl test EffectRowTest`,
`ModuleScopeTest`, `Workspace`, `Manifest`, `TypeCheck`, `Parser`, `Formatter`,
`wl lib` for every package, `wl docs`. Likely trouble:

- Parser: `StartsUnsafeFunction` is the only place `unsafe fun` is told from the
  `unsafe {` block; `SkipToItemBoundary` and the nested-item test use it.
- `ItemFlags::kUnsafe` took bit 15, the last of a `uint16_t`. The next flag
  needs a wider type and a cache change. `Cache::kVersion` is 4.
- `database.cc` effect diagnostics: an `unsafe fun` with a `uses` clause adds
  `unsafe` to its stated row; without one it only escapes E0704 for `unsafe`
  itself (`visible` row), so `offer unsafe fun` that also does `io` is still
  E0704. Methods are not checked there (they never were).
- Library: bodiless `uses unsafe` became `unsafe fun` in std.mem, `TextFromRaw`,
  `ParallelFor`, `game.RunSystems`. `AtomicAdd`, `socket.Read` and
  `gfx.TextFromC` have bodies and were migrated too, so their callers now pay;
  `wl lib` shows any caller that did not state `uses unsafe`.
- `E0153` is not raised for `extern` functions, `extern class` methods or ability
  methods; the test `bodiless-extern` assumes an `extern ... uses unsafe` parses.
- Allocation: `TypedBody::allocation` has one frame per function or method with
  an item-tree index (`CheckFunction` owner); local functions and closures count
  for the enclosing frame. `RecordCallEffects` reads `binding->real_name` for the
  `ArrayNew`/`SoaNew` names. `NoteCall` feeds the callee edges, so the edges are
  the same ones D232 uses.
- `kAllocation` is keyed with argument 0 and reads every module's `TypeCheck`;
  `ProgramAllocation::Find` needs the nodes sorted, which the query does.
- Removing `BuiltinEffect::kAlloc` shifts every built-in id. Nothing numeric
  should depend on it, but the cache version was bumped for it.
- `E0158` fires on any name in `uses` that `FindEffect` cannot resolve. If an
  imported effect fails to resolve in some file, `wl lib` will show it; the
  fallback is to fire only for `alloc`.
- The bodiless-function-returning-owned-text rule may blame intrinsics that do
  not allocate; check with a grep of `lib` for such signatures if `wl lib` shows
  a surprising E0155.
- `docs/api/*.md` still shows `uses unsafe` on the migrated signatures; regenerate
  them with the doc tool.

## Unverified D240

D240 (F1 and F2) is written in seven commits, with no build. Compile first, then
`wl test Parser`, `Formatter`, `TypeStoreTest`, `TypeCheck`, `LowerTest`,
`CodegenTest`, `AotTest`, `wl lib` for std and http, `wl docs`, `wl fuzz 200`,
and an asan run of `CodegenTest.AnEscapingClosureOwnsWhatItCaptured`. Likely
trouble:

- The kept bit is on `Type` (`is_kept`) and makes two function types distinct
  ids. `Accepts` ignores the top-level bit; `TypeStore::SameShape` is what the
  verifier uses at calls and edges. Any other place that compares function
  `TypeId`s with `==` (a `Coerce`, a generic key, an override check) can now see
  a difference that did not exist. `Erase` keeps the bit, so the IR types differ.
- `TypeStore::Function` defaults to kept. The plan said borrowed; kept is safer
  because only `ResolveParameter` makes a borrowed one.
- Parser: `keep_allowed_` is set before each parameter type and each parameter
  of a `fun(...)` type, and cleared at the top of `ParseType`. A parameter named
  `keep` still parses (the word is contextual).
- Checker: `KeepInto` runs at return, expression-body return, assignment `=`,
  `const`/`var` with an annotation, module-level init, call arguments (plain and
  generic) and constructor arguments. Not covered: array and tuple elements,
  variant payloads, struct literals. Inferred type arguments are made kept in
  `Instantiate` and in the generic call path.
- `E0136` is gone: `ACapturingClosureCannotOutliveItsFrame` was rewritten.
- Lowering: `Counts` now includes a kept function, so every place that retains
  or releases a class handle does the same for the environment word (second
  word). A non-escaping capturing closure still has a frame environment with a
  count nobody reads, and is never typed kept, so it must never be retained.
  If a stack environment is ever retained, that is the bug.
- Escaping environment: `kNew` at the closure site (not hoisted to entry),
  field 0 the address of `closure$N$drop`, captures from field 1
  (`PendingClosure::first_field`). The drop is called through `kCallIndirect`
  with the environment as a word, the convention closures already use.
- Moved captures: lowering clears the owner flag of a deinit value
  (`FlagOf`), flow marks the outer name moved after the closure. A captured
  parameter with a `deinit` has no flag; check that it is not dropped twice.
- Known leak: a fresh closure stored into an inferred-borrowed local is retained
  and never released.
- `docs/api/*.md` still shows function parameters without `keep`; regenerate
  them with the doc tool.

## Not done in 1.2.0

Phase B, the known gaps: `var a: s8 = -128` traps; `"{t}"` of an owned `Text`
in a loop is E0122 on the second pass; qualified names in patterns, as
intrinsic callees and as assignment targets (D246); `E0147` across modules and
method calls; a read-only slice (D233); a deadline on blocking `Serve`; LLVM
component libraries leaking into AOT install packages.

Phase C: `math` (vectors with operators, now possible), then `font`, `audio`,
`gpu`, `ui`, `app`. Move the last five to 1.3.0 if time runs out.

Phase D, groundwork for self-hosting: check `std` for what a compiler needs
(fast `Map`, arenas, text building, files, process), build the IR reader, and
write a throwaway Wolang lexer for Wolang to find the gaps.

Release gate: `wl ci`, `wl fuzz 200`, `wl docs`, CI green on every platform,
then STATUS.md, CHANGELOG.md and the `wolang-wrapup` skill. Then the PR from
`feature/1.2.0` into `alpha`. Its body should list D238, D239, D250 and every
item above that landed, and say plainly what is under "Not checked".

## After 1.2.0

1. **Self-hosting**, stage by stage as in [self-hosting.md](self-hosting.md)
   (D250): tools in Wolang, then lexer and parser, then sema and lowering, then
   the driver built by AOT with the C++ compiler kept as the bootstrap.
2. **What the engine needs.** [engine-needs.md](engine-needs.md) has 25 numbered
   bugs the engine team reproduced, and a list of suggestions they have not
   checked against this repo. A first sorting, to be confirmed against the
   code before anything is promised:
   - Language, fit for 1.2.0 or 1.2.x: 20 (alias across packages), 21
     (`extend` of a foreign class), 22 (`if const` on optionals, `?.` with a
     method call), 24 (false unused-import warning), 23 (`after` in
     `machine`), and 2 (module-level `weak var`).
   - Embedding API, a 1.3.0 theme: 1, 4, 17, 18, 25 (objects and structs across
     the boundary); 5, 8, 11, 12, 3 (writer, per-VM bindings, `need` for a
     single file, module-qualified names, release on destroy); 14, 15, 13, 16
     (generator coverage).
   - Lifetime and safety: 9, 10, 19.
   - Hot reload: 6 (migrate live objects), 7 (a failed reload keeps the old
     program).
   - Game-language features, each needs a design decision first: replication
     attributes, a debug protocol, an execution budget, coroutines tied to the
     game clock, serialization, a versioned binding ABI, sandboxing, AOT without
     a system `cc`, published benchmarks.
   Item F (Linux AOT needs `cc`) is the environment, not a bug, but "AOT with no
   system `cc`" is on the engine's wish list.

## Traps met this session

- On Windows `wl` defaults to the `debug` preset, which fails on CRT
  deprecation warnings. Use `WL_PRESET=windows`. (Also in `.claude/memory/gotchas.md`.)
- Run one build or test process at a time. Overlapping runs clobber each other,
  and two `wl lib std` runs hang, probably on the loopback port.
- `wl wo new` writes backslashes into the manifest's std path on Windows; it
  then fails to resolve std. Rewrite the path with forward slashes.
- Structs are built positionally, `Paint(Colour.Blue, -1)`.
- Do not commit to `alpha`. Work for the next version goes on `feature/<version>`.
- No `Co-Authored-By` trailer in commits (the owner's rule).

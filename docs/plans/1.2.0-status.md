## Unverified D235

Compile first, then run `wl test TypeCheck`, `CodegenTest`, `AotTest`, `wl lib`,
`wl docs`, `wl fuzz 200`. Likely trouble:

- `Parser::ParseErrorList` and the `!` loop: an identifier after `!` on the same
  line is read as an error name.
- `TypeStore::StatedErrorSet` pre-interns `Optional(detail)`; `FindOptional` in
  the layout depends on it.
- `Erase(kFallible)` keeps only payload errors in the set; every comparison of an
  erased fallible with an unerased one is a place to look.
- `Coerce` into a `T!`: the boxed branch and the rebuild between two payload
  layouts, and who frees a slot after `?` (`IsFreshHandle` on `MakeStruct`).
- A payload error held in a `const` before it reaches a `T!` is a tuple and is not
  counted: it leaks its box.
- Library sets were read off the code by eye (client, image, db, json, yaml,
  toml, regex, compress); `wl lib` will show any missing one as `E0151`.
- Test sources that match on a bare `T!` with no `_` arm are `E0201` now; the ones
  in `codegen_unittest.cc`, the libraries and the docs were changed by hand.
- Tag-hash collisions between two modules are not diagnosed (plan said E0057).
- The three parser/formatter/lowering tests were first written with real newlines
  inside string literals and rewritten in the fuzzer commit.

## Not done in 1.2.0

Phase A, in this order:

1. D236: `unsafe fun`.
2. D237: `@Hot` checks allocation.
3. D240: escaping closures with `keep` (F1-F2; F0 is in).

Phase B, the known gaps: `var a: s8 = -128` traps; `"{t}"` of an owned `Text`
in a loop is E0122 on the second pass; qualified names in patterns, as
intrinsic callees and as assignment targets (D246); `E0147` across modules and
method calls; a read-only slice (D233); a deadline on blocking `Serve`; LLVM
component libraries leaking into AOT install packages.

Phase C: `math` (vectors with operators, now possible), then `font`, `audio`,
`gpu`, `ui`, `app`. Move the last five to 1.3.0 if time runs out.

Phase D, groundwork for self-hosting: check `std` for what a compiler needs
(fast `Map`, arenas, text building, files, process), build the IR reader, and
write a throwaway Wolang lexer for Wolang to find the gaps.

Release gate: `wl ci`, `wl fuzz 200`, `wl docs`, CI green on every platform,
then STATUS.md, CHANGELOG.md and the `wolang-wrapup` skill. Then the PR from
`feature/1.2.0` into `alpha`. Its body should list D238, D239, D250 and every
item above that landed, and say plainly what is under "Not checked".

## After 1.2.0

1. **Self-hosting**, stage by stage as in [self-hosting.md](self-hosting.md)
   (D250): tools in Wolang, then lexer and parser, then sema and lowering, then
   the driver built by AOT with the C++ compiler kept as the bootstrap.
2. **What the engine needs.** [engine-needs.md](engine-needs.md) has 25 numbered
   bugs the engine team reproduced, and a list of suggestions they have not
   checked against this repo. A first sorting, to be confirmed against the
   code before anything is promised:
   - Language, fit for 1.2.0 or 1.2.x: 20 (alias across packages), 21
     (`extend` of a foreign class), 22 (`if const` on optionals, `?.` with a
     method call), 24 (false unused-import warning), 23 (`after` in
     `machine`), and 2 (module-level `weak var`).
   - Embedding API, a 1.3.0 theme: 1, 4, 17, 18, 25 (objects and structs across
     the boundary); 5, 8, 11, 12, 3 (writer, per-VM bindings, `need` for a
     single file, module-qualified names, release on destroy); 14, 15, 13, 16
     (generator coverage).
   - Lifetime and safety: 9, 10, 19.
   - Hot reload: 6 (migrate live objects), 7 (a failed reload keeps the old
     program).
   - Game-language features, each needs a design decision first: replication
     attributes, a debug protocol, an execution budget, coroutines tied to the
     game clock, serialization, a versioned binding ABI, sandboxing, AOT without
     a system `cc`, published benchmarks.
   Item F (Linux AOT needs `cc`) is the environment, not a bug, but "AOT with no
   system `cc`" is on the engine's wish list.

## Traps met this session

- On Windows `wl` defaults to the `debug` preset, which fails on CRT
  deprecation warnings. Use `WL_PRESET=windows`. (Also in `.claude/memory/gotchas.md`.)
- Run one build or test process at a time. Overlapping runs clobber each other,
  and two `wl lib std` runs hang, probably on the loopback port.
- `wl wo new` writes backslashes into the manifest's std path on Windows; it
  then fails to resolve std. Rewrite the path with forward slashes.
- Structs are built positionally, `Paint(Colour.Blue, -1)`.
- Do not commit to `alpha`. Work for the next version goes on `feature/<version>`.
- No `Co-Authored-By` trailer in commits (the owner's rule).

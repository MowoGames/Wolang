## Принятые решения (не пересматривать без причины)

1. **Отдельный проект**, не модуль движка. Движок — один из хостов, адаптер к
   нему появится в волне 15.
2. **Память — гибрид:** значения с mutable value semantics, ссылки второго
   класса (нельзя хранить в полях), `Box`/`Rc`/`Arc`, `region` для кадровых
   арен, `class` + GC как **опциональный** компонент.
3. **Эффекты и capabilities** — один механизм вместо пяти проверок: выводятся
   внутри модуля, объявляются явно на `pub`-границах.
4. **В ядре языка четыре подписные фичи:** единицы измерения, AoS/SoA +
   SPMD `foreach`, автоматы `machine`/`state`, реактивные `derived`.
5. **Контекстные ключевые слова** (`state`, `unit`, `machine`, `derived`,
   `effect`, `dimension`, `enter`, `exit`, `always`, `with`, `without`)
   лексятся как идентификаторы — их имена слишком часто нужны геймплейному
   коду.
6. **Суффикс единицы в числе — просто символ.** Список единиц
   пользовательский, разрешает его Sema, а не лексер.
7. **Стандартная библиотека на Wolang** поверх тонкого C++-слоя платформы;
   интринсики (`memcpy`, атомики, SIMD, `sqrt`) опускаются прямо в IR.
   `core` станет возможен в волне 7.
8. **Самохостинг компилятора не планируется.** Компилятор — C++20.
9. **Код-стайл Chromium везде**, без исключений и RTTI; коммиты —
   Conventional Commits одной строкой без тела и без co-authored.
10. **arm64 раньше x64** для Dev-кодогена (машина разработки).
11. **Интерпретатор IR — эталон семантики**, а не временный костыль: JIT, AOT
    и WASM сверяются с ним дифференциальным фаззингом.
12. **Документация `docs/` — на английском** (публичные артефакты языка),
    `STATUS.md` — на русском.
13. **Управляющие конструкции — выражения** (`if`, `match`, `loop`, `while`,
    `for`, `foreach`, `unsafe`, `region`, блок). `let x = if c { a } else { b }`
    работает без спецслучаев.
14. **`as` — оператор приведения** (открытый вопрос волны 1 закрыт).
15. **Турбофиша нет:** `f<T>(x)` разрешается просмотром токенов вперёд.
16. **Точка в выражении — всегда доступ к члену.** `World.Spawn` станет путём
    только после разрешения имён (волна 4).
17. **Оператор в начале строки начинает новый оператор-строку**, а не
    продолжает выражение; исключение — `.` и `?.` для цепочек методов.

## Что делать в волне 3

Цель: правка тела функции пересчитывает только её; модули и пакеты есть.

1. `include/wolang/query/` — база запросов с red-green инвалидацией:
   `QueryEngine`, ключи запросов, журнал зависимостей, ревизии.
   Первые запросы: `SourceText`, `Tokens`, `ParseFile`, `ItemTree`,
   `ModuleScope`.
2. `ItemTree(file)` — объявления без тел: имена, видимость, сигнатуры-заготовки.
   Главное свойство: правка тела функции **не меняет** `ItemTree`, поэтому
   зависимые запросы остаются зелёными.
3. Манифест пакета `wolang.toml`: имя, версия, зависимости, уровни линтов
   (`[lints]`), политика `unsafe`. Парсер манифеста — свой, минимальный TOML.
4. Граф модулей: `import` разрешается через граф пакетов, циклы между
   пакетами — ошибка, внутри пакета разрешены. Коды `E0050`–`E0069`.
5. Сериализация базы в `.wolang-cache/` — холодный старт не перепарсивает
   неизменённые файлы. AST уже плоский, так что дамп массивов достаточен.
6. `wolang fmt` — форматтер поверх AST + таблицы комментариев из лексера
   (`TokenStream::comments`), с `--check` для CI.
7. Тесты: инвалидация (правка тела → один пересчёт; правка сигнатуры →
   пересчёт зависимых), холодный старт из кэша, разрешение импортов,
   идемпотентность форматтера (`fmt(fmt(x)) == fmt(x)`).
8. Закрыть волну: `docs/architecture.md` (раздел про запросы),
   `docs/diagnostics.md` (коды модулей), `docs/waves/wave-03.md`, этот файл.
